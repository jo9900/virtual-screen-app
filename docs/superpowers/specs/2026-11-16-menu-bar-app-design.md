# Virtual Screen menu bar app — design

Date: 2026-11-16. Status: approved in conversation (approach A), then retargeted from a Developer ID
DMG to the Mac App Store at the owner's request.

## Intent

Turn the `virtual-screen` CLI into a macOS menu bar app sold on the Mac App Store (JPY 1,000, every
territory available). The owner runs a headless Mac mini through RustDesk; the app replaces
BetterDisplay's paid virtual screen. Everything up to "Submit for Review" is prepared for the owner,
who reviews and submits personally.

## Goals

- Menu bar app (no Dock icon) that owns a `CGVirtualDisplay` and makes it the main display.
- Pick 1920x1080, 2560x1440, 3200x1800 or 3840x2160, HiDPI on or off, from the menu.
- Turn the virtual screen on and off without quitting.
- Start at login (system login item, with consent); remember resolution, HiDPI and on/off.
- English, Japanese and Simplified Chinese UI.
- App icon designed for this app.
- App Store package, screenshots and store listing text (en, ja, zh-Hans).

## Non-goals

- Custom resolutions, multiple virtual screens, mirroring.
- Developer ID DMG or GitHub releases (they would undercut App Store sales).

## Anti-goals

- Surprising lifecycle behavior (an app that quits itself or refuses to open).
- Anything system-wide or needing `sudo`.
- Hiding the private API from App Review.

## Known risk

`CGVirtualDisplay` is private API. App Review Guideline 2.5.1 allows public APIs only, and macOS has
no public virtual display API, so the review may reject the app. The owner decides whether to submit.

## Approaches considered

- **A. Ordinary login-item app (chosen).** The app process owns the display; `SMAppService.mainApp`
  starts it at login. If the system terminates the display, the app recreates it. If the app
  crashes it is not restarted. SSH recovery: `pkill -x "Virtual Screen"`, plus
  `defaults write io.github.jo9900.VirtualScreen isEnabled -bool false` to skip the display on next
  launch.
- B. App registered as a LaunchAgent via `SMAppService.agent`. Keeps crash restart and
  `launchctl bootout`, but turning off "start at login" would quit the app, and opening the app
  while it runs would exit the new copy. Rejected for those surprises.

## Decisions

- The app replaces the CLI and its install scripts.
- Project generated by XcodeGen (`project.yml`); the generated `.xcodeproj` is not committed.
- Shared logic lives in the local Swift package `Packages/VirtualScreenCore` (resolutions, mode
  plan, display creation and configuration, private API header).
- Resolution changes while running switch the display mode in place (every preset is registered
  at 2x and 1x), so the display is not recreated.
- When the mode is changed in System Settings and matches a preset, the app adopts it as the
  saved choice.
- First launch asks whether to start at login (Guideline 2.4.5 forbids adding it without consent).
- App Sandbox on (verified: `CGVirtualDisplay` and display configuration work inside it),
  hardened runtime on.
- Bundle ID `io.github.jo9900.VirtualScreen`, product name "Virtual Screen", macOS 14+,
  team `54BTJHJKUU` (the owner's individual account).
- Strings in a String Catalog (`en`, `ja`, `zh-Hans`).
- Menu bar glyph: SF Symbol `display`. App icon: original Icon Composer artwork (SF Symbols may not
  be used in app icons).
